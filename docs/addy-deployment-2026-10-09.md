## Resource, privacy and retention facts

App1CPU/512MiB; MariaDB0.5CPU/256MiB; Redis0.25CPU/64MiB with32MiB no-eviction limit; gateway0.25CPU/64MiB. Processes and Docker logs are bounded; Docker logs rotate1MiB×2. The upstream all-in-one entrypoint needs a writable root and default Docker capabilities to configure native Postfix/s6 and drop privileges; it is not privileged and has no host mounts or Docker socket. The gateway/Redis are unprivileged with read-only roots. No-new-privileges applies.

No visitor analytics, advertising or external account-authentication provider is configured. Native mail authentication uses local Rspamd and DNS; it is separate from account sign-in. CSP limits browser assets/connections to this instance. Tested browser login and CSV export made no external requests. Incoming/forwarded email is processed in readable form; optional recipient OpenPGP is an upstream capability, not an end-to-end guarantee for all mail. Alias addresses, recipient/account settings, encrypted-at-rest recipient fields, delivery counters and failed-delivery metadata are server data. Encryption keys are operator-held; this is not zero-knowledge storage.

The native Postfix queue lives in the persisted app directory. Its inspected active maximal and bounce queue lifetimes are5days. These are retry lifetimes, not a promise that every copy disappears after5days. Failed-delivery metadata and optional saved `.eml` files are cleaned by the installed native command after7days; its human-readable command description incorrectly says3days, but executed code uses7. The native scheduler runs the cleanup daily, and outbound-message records are cleaned after7days every6hours. Delivery counters/aliases/recipient settings are not covered by that expiry. Shared-domain alias tombstones and deleted-username reservations can remain to prevent reassignment.

Gateway access logs are off. Native nginx/PHP/Postfix operational logs can contain IPs, recipient/alias/sender identifiers and request details. Laravel uses its native14-day daily-file rotation. A scoped logrotate timer checks Postfix and Laravel files every5minutes, rotating files at1MiB with2older copies; they can temporarily exceed the threshold between checks. Docker output is separately size-rotated. No fixed universal log duration is claimed. Public data notes must retain these distinctions when the service is listed.

## Native account, export and deletion scope

EN: Sign in, create an alias and choose a verified recipient. Deactivating an alias stops forwarding without deleting its record. **Settings → Account Data → Export Alias Data** downloads CSV alias records. The downloaded native file includes alias attributes/counters and descriptions, not a complete account, mail archive, signing keys or server configuration. The import feature is a separate CSV template with exactly `alias,description,recipients`; the richer export is not directly the accepted import format. Import is limited to the account’s custom domains, valid recipients and 1,000 rows per file; existing aliases are skipped. It does not recreate shared-domain aliases, recipient relationships or the complete account from the richer export. No import round trip is claimed.

ES: Iniciá sesión, creá un alias y elegí un destinatario verificado. Desactivar un alias detiene el reenvío sin borrar su registro. **Settings → Account Data → Export Alias Data** descarga los registros en CSV. El archivo nativo incluye atributos, contadores y descripciones de alias; no es una copia completa de la cuenta, los mensajes, las claves de firma o la configuración. La importación usa otra plantilla CSV con exactamente `alias,description,recipients`; el archivo exportado más amplio no es directamente el formato de importación. La importación se limita a tus dominios personalizados, destinatarios válidos y 1.000 filas por archivo; omite alias que ya existen. No recrea alias del dominio compartido, asociaciones de destinatarios ni la cuenta completa a partir de la exportación más amplia. No se afirma una importación de ida y vuelta probada.

Account deletion uses the native password-confirmed account action/API. It revokes tokens and removes the user, recipients, rules and other account records; shared-domain aliases may remain as deactivated tombstones with identifying description/counters cleared. Recipient mailboxes, forwarded messages and old backups are separate copies. External/proxy-auth account deletion has different restrictions and is currently disabled, not silently promised.
