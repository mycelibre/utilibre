# Dated records

These files preserve deployment decisions and verification from the date in
each filename. They are evidence for the current service and maintenance
guides in the parent directory, not a statement that every historical finding
is still open. Start with [services](../services.md),
[updates](../updates.md) or the [current work queue](../work-queue.md), then
follow their links to the relevant record. Each former record path contains a
short link to its new location, preserving existing GitHub and source-package
URLs.

Do not change a record's date merely to suggest a fresh review. Add later
observations to the current guide or to a new dated record when needed.
