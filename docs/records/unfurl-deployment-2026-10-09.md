The native graph-based URL parser/UI is installed. A small configured mode in its existing shortlink parser reuses its HTTP Location-header reader for full HTTP(S) URLs and relative redirects. At most ten distinct URLs and 100 graph nodes; repeated URLs stop. Configured mode uses HEAD and closes each response after headers. There is no GET fallback: servers rejecting HEAD may not expand. This matters because Python Requests consumes redirect bodies while preparing its next request even with GET stream=True/allow_redirects=False; HEAD avoids that hidden read. Other parsers' remote lookup flags are disabled: no remote hash lookup, social enrichment, Bitly API, LinkedIn interstitial scraping, preview fetch or destination scripts. Credentials and non-80/443 ports are rejected. JavaScript/meta-refresh/consent-page redirects are unsupported. An unexpanded node is not proof that a link has no further destination or is safe.

URLs reach Utilibre's server. Remote destinations and DNS resolvers see the requests needed for expansion; a one-time or per-recipient link can be consumed or register engagement. Never submit private tokens/passwords/confidential links. The upstream browser route and API use URL query strings: submitted URLs can remain in browser history and are visible at TLS termination. This is SERVER/EXTERNAL processing, not LOCAL, a malware scanner or anonymity service. No analytics were added. No database/content cache/state volume exists; only the upstream theme preference persists in localStorage. The browser URL/results and copied text are separate data. There is no user-data backup/export server because this service stores none; native Text view copies the result tree. Browser history and copied/downloaded text remain under user control.

Privacy adaptations are reversible in `source.patch`: bounded header-only mode, remote parser restrictions, close response bodies, API length limit, CORS restriction, local assets, native tooltip sanitization, EN/ES voseo notices and More tools/source links, and narrow-screen input sizing. Graph dependency localized and upgraded from old vis4 to vis-network10.1.2; d3 7.9.0 and DOMPurify3.4.16 are local with pinned SHA256 and licence notices. No additional frontend/backend was built. Core native unit/regression suite: 408 tests pass. Runtime's 37 exact Python dependency pins passed pip-audit with no known vulnerabilities on this date. This is not a security certification.

## Runtime boundary and recovery

Two native Gunicorn workers, 15-second worker deadline, one thread each, 256MiB/1CPU/48PID ceiling. Native modules preload before fork. The headers-only mode skips unused bulk domain-reputation list enrichment: keeping it caused copy-on-write pressure near512MiB even with preload. The configured mode therefore provides URL parsing/expansion without those optional reputation annotations. Gateway64MiB/0.25CPU, proxy192MiB/0.5CPU. Nginx allows two active expansion requests globally, two/client and six new requests/minute/client with burst2; 4096-character input cap, no request bodies needed, 18-second gateway timeout. These are configured limits, not a measured public capacity promise.

App only has an internal Docker network. Native requests uses a fixed HTTP(S) proxy, no NO_PROXY bypass, no application DNS resolver. Separate Squid7.7 native proxy resolves outbound targets and rejects nonpublic addresses and unsupported methods/ports. HTTP GET/HEAD and CONNECT443 only, selected existing VM resolvers1.1.1.1/9.9.9.9, native header/time/body bounds, no HTTP cache/access log, no forwarding of client cookies/auth/IP. Image `utilibre-public-egress:7.7`, initial local image ID `sha256:9bc66d80e90a72c29ba89d44447b58bd1faded54b4ecba35b4f7b2b23497c780`; shared reproducible build recipe `deployment/13ft/Dockerfile.proxy` pins upstream7.7 tarball SHA256. This avoids the open Squid6.13 advisories found during review. Separate proxy container/networks from13ft.

Host DOCKER-USER filtering alone does not see same-bridge traffic on this VM: the bridge netfilter sysctl is unavailable. `start-boundary.sh` therefore also installs OUTPUT rules inside each service's own network namespace. Proxy rejects new connections to every listed nonpublic IPv4 class before permitting public80/443 and only selected DNS; IPv6 transport disabled. App permits only its fixed proxy3128 and own health endpoint; gateway permits only app5000 and own health endpoint. Existing connections permit return traffic. These rules protect the actual selected destination even if DNS changes after an application-level check. Containers have no NET_ADMIN/capabilities and cannot remove them.

Scoped systemd `utilibre-unfurl.service` starts the boundary before opening the gateway; restart:no prevents containers auto-starting around it. Startup first stops only this stateless project, applies host rules, starts the proxy and its namespace rules, then app/rules, then gateway/rules. No global bridge modules or other services are changed. Docker content logs disabled and compose output detached from all containers; native access logs disabled. This does not promise absence of edge, kernel/security, provider or DNS records.
