## Access, storage and network

Existing Authentik native OIDC accepts the approved, email-verified group. Local login and signup are disabled. Tasks, projects, comments, attachments, account identifiers and access/session metadata are readable server-side; this is not end-to-end encrypted storage. Link sharing remains available: recipients can access content according to the native share's rights. Discoverability by name/email is off by default. Browser preferences and downloaded exports remain on the device until cleared/deleted.

Sentry backend/frontend, metrics, Pro activation, webhooks, external import integrations and Unsplash are disabled. Uploaded backgrounds and initials avatars work. The native Gravatar provider URL points at an unavailable local endpoint, so no email hash is sent externally; its unavailable UI choice is disclosed in the native MOTD. Remote Markdown images are blocked by the gateway CSP. OIDC contacts Utilibre's identity endpoint; ordinary traffic through the eventual public Cloudflare/Caddy path has the same provider boundaries documented for other proxied Utilibre hosts. External email reminders are disabled. Self-service account deletion requires email confirmation upstream, so use the existing private operator contact for native account removal while mail is disabled. No visitor analytics were added.

The app has 1.5 CPU, 768 MiB and 128 PID ceilings; gateway 0.25 CPU/64 MiB. Uploads: 10 MB per native attachment. Import limits: 20 MB ZIP, 1,000 files, 100 MB imported storage. These are per-operation limits, not an account storage quota. Native authenticated requests are limited to 600/minute; anonymous requests to 100/minute, with bounded gateway request bursts. Native HTTP/database/event/mail logs are off. Warnings/errors remain, with Docker rotation 2 × 5 MB per container; this is size-based, not a promised number of days. Separate edge/provider log retention is not established here.

## Native export and deletion

Settings → Export your data requests the native ZIP; return to the export page to download it when ready. No email is sent on this installation. The export contains projects/tasks, their attachments, saved filters and project background files. It is not a complete identity, session, permissions, team or account-settings migration. Import through Settings → Import your data → Vikunja into a compatible installation. Import creates copies; it does not replace existing projects. Protect downloaded ZIPs as plaintext personal data. Generated export files expire after seven days through the native cleanup task; ordinary task content has no configured automatic expiry.

Delete tasks/projects through their native menus. Removing a share revokes that link, not copies already downloaded. Account removal through the native operator CLI revokes/removes that account's stored application state; discuss shared/team ownership before deleting a real account. This verification deleted only a disposable account. Existing backups may retain earlier data: daily same-VM backups have **no configured automatic deletion schedule**, and are not protection against loss of the physical server.

Only the verified disposable `utilibre-check-a` application account was subsequently removed through native `user delete --now --confirm`; no real account was read or changed.

Run `python3 deployment/community/vikunja-backup.py` for a consistent native dump plus private configuration/secrets/checksums. The serial `utilibre-community-backup.timer` runs daily around 04:25 UTC with a 15-minute randomized delay, stopping only each respective backend briefly and restarting it in `finally`. Its first run completed successfully after fixture cleanup. Keep backup files private. Do not run `restore` against live state: create an empty recovery directory, preserve the pinned image/config/secrets and follow `check-vikunja-restore.py`. Its HTTP assertions are necessary because the upstream restore command can log an error but exit zero. The fictional restore check refers to the fixture snapshot, not the later empty post-cleanup snapshot.
