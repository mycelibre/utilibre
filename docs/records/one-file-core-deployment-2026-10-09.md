# The One File Core deployment, 9 October 2026

Standalone Core 4.1.5, upstream commit `b988be00cc35fe1a7d7756543b326287f2e4ebf5`, Utilibre p1. The upstream [repository and licence](https://github.com/gelatinescreams/The-One-File/tree/b988be00cc35fe1a7d7756543b326287f2e4ebf5) were checked on this date; the licence is Unlicense. The latest repository release tag describes Verse, not a later Core binary; the inspected Core source identifies itself as 4.1.5. GitHub's public advisory endpoint returned no published advisories. That is not a security certification. No npm/runtime dependency installation is needed.

Public entry: `https://tools.utilibre.org/apps/one-file-core/`; Spanish: `/apps/one-file-core/es/`. These are static download pages, not a hosted diagram editor. `one-file-core.html.download` is served as `application/octet-stream` and the native download attribute supplies `one-file-core.html`. Users open their copy locally. This keeps imported rich HTML away from the shared tools site's origin. No iframe wrapper, collaboration backend, extra container, public port or identity account is added. The existing tools static server and resource ceilings are reused; diagram processing is on the user's device. Native controls remain English; operator notices and guides have equivalent EN/ES text with voseo.

## Privacy and narrowly patched defects

Core has no automatic remote fetch, STUN, collaboration or network-monitoring dependency. This is not the Networkening or Verse edition. The package adds a restrictive in-file CSP blocking external connections/resources, retained by HTML saves, and noindex/referrer metadata. External links deliberately opened by a user remain separate navigation. The website and providers see application downloads and normal connection metadata; no diagram upload endpoint exists. Do not infer provider/edge log retention from static application behavior.

Native IndexedDB autosaves run every 30 seconds; local recovery snapshots (up to 50) and edit records (up to 1,000) can survive tab closure. They are personal editor state, not server visitor analytics, and are readable local data. Downloads and independent backups are separate. File-URL storage handling varies between browsers. Settings → Clear All removes native editor working/recovery state; it does not erase downloaded copies. No operator backup contains users' local diagrams in this workflow.

The pinned source had two demonstrated defects relevant to this deployment:

- Saving JSON in HTML script elements without escaping `<` allowed literal `</script>` in fictional text to terminate the data element. Four assertion-gated serialization replacements preserve the text as JSON escapes. The saved/reopened node name was verified byte-for-byte.
- Native Encrypt saved encrypted state but still serialized the selected node's name and IP as readable sidebar HTML. The fictional encrypted export contained both markers and decrypted successfully. New encrypted-HTML creation is disabled with a disabled native toggle and a false save-branch predicate. Native opening/decryption code and ordinary imports remain unmodified. Native HTML import itself accepts plain Core state, not an encrypted payload; opening an older encrypted HTML uses the application embedded in that older file. No claim is made that older Core encrypted files are fully confidential. For confidentiality, encrypt the completed HTML as a whole with the existing hat.sh application, then manage old plaintext files and browser drafts separately.

The patch is `deployment/one-file-core/standalone.patch`; it also adds a bilingual notice inside the existing Help panel and corrects the old encryption instruction. It does not change node editing, monitoring, storage expiry or add a sanitization framework. Remove the serialization/creation restrictions only after an upstream release passes script-text round trips and complete encrypted-output leak checks across rendered document surfaces. Treat imported HTML/notes/language files as trusted executable documents.

## Verification and reproduction

`python3 deployment/one-file-core/build.py` checks the exact Git pin, retrieves the immutable HTML through Git, applies the patch with zero fuzz, preserves the upstream licence and emits `build.json` hashes. No package manager or container build runs. Repeating the build produces the same HTML hashes.

`node deployment/one-file-core/check.mjs URL` tests real browser downloads, native fictional-node creation, disabled encryption creation, HTML save and reopening in a fresh context, literal script-closing text, retained CSP, native autosave and Clear All. English desktop and Spanish-locale 390px touch workflows passed; the Core controls remain English. No external HTTP request occurred. Phone operating-system file handlers are not represented by Chromium viewport emulation. Native Fit to view was independently checked. Evidence and fictional fixtures: `/opt/utilibre/reports/single-file-20261009/`.

Deployment copies the built directory to a new hidden staging directory under `/opt/utilibre/toolbox-public/apps/` and atomically renames it to `one-file-core`. Existing data directories and backups are untouched. Future replacement retains the old static directory for rollback; there is no database migration. Source offer: `https://tools.utilibre.org/utilibre-source/one-file-core-utilibre.tar.gz`, containing the pinned Core source, original licence, upstream relevant documentation and exact patch/build/check/landing files. `build.json` is an artifact manifest, not a record of users.
