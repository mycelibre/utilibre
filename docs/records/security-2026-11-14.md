## Remaining ACL issue and exact next action

Debian still lists the installed stable ACL versions as vulnerable. The 2.4
change adds descriptor-relative APIs; existing privileged callers must use
them. Replacing libacl alone is not proof of closure, and changing legacy
symlink behavior globally can break legitimate tools. Debian also documents a
tar symbol compatibility problem. We did not install unstable ABI changes,
alter access controls or suppress these 30 records. A compatible native
library **and caller** update with positive/negative filesystem regression
tests is needed. Existing containment is not called a patch.

The kernel maintenance window and guest-side post-reboot checks are complete.
Proxmox-side guest-agent ping/thaw confirmation has been requested separately.
The separate Proxmox/Caddy hosts and physical CPU/firmware are
not inspected or cleared by this VM's package scan.
