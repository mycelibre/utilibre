## Gateway restart loop

The Binternet onion gateway repeatedly failed with `Address in use` after the
host reboot. Its shared `http.sock` inode survived, but connecting returned
`ECONNREFUSED`: there was no live listener. Startup now checks that exact socket
and removes it only when curl reports connection failure. It refuses to remove
a responding/timed-out listener or a non-socket file. The gateway uses SIGQUIT
for graceful shutdown and has an HTTP health check through the Unix socket.
Tor identity and application data were preserved.

An isolated container test verified recovery from an abandoned socket and a
forced process kill, preservation of a live listener and ordinary file, and
socket removal on graceful shutdown. The production gateway returned HTTP 200,
became healthy, and retained zero restarts throughout the checks.

The host's console verbosity is persisted in
`/etc/sysctl.d/99-utilibre-console.conf` as `kernel.printk = 3 4 1 3`.
Routine kernel events remain in the journal; critical console alerts remain.
See the [kernel printk documentation](https://docs.kernel.org/admin-guide/sysctl/kernel.html#printk)
and [Nginx shutdown signals](https://nginx.org/en/docs/control.html).
