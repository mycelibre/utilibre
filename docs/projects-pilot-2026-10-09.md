## Implementation and security review

The small source patch changes only four package/lockfile files. Server production dependencies were refreshed within compatible lines, including current body-parser, compression, proxy-addr, qs and CommonJS-compatible uuid. The resulting server audit had no high/critical reports; three moderate package reports trace to sprintf-js through i18n-2/Sails. The native `.sailsrc` already disables the i18n hook, and no application-supplied formatting path was found. This scoped result is not a claim that the application has no vulnerabilities.

The client review inspected the actual compiled browser source maps. The originally reported advisory packages present as mapped browser modules were parseuri and React Router. React Router was upgraded to 7.18.4, addressing the [navigation issue](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6) and [SSR hydration issue](https://github.com/advisories/GHSA-337j-9hxr-rhxg). Projects itself uses the plain client Router rather than SSR hydration. Native routing must continue to pass the browser check whenever the dependency is changed.

The original parseuri 0.0.6 dependency and its [advisory](https://github.com/advisories/GHSA-6fx8-h7jm-663j) remains in its Socket.IO 2 dependency. Version 3 changes both its export and returned field names and is not a compatible override; an isolated attempt was reverted. Inspection of `client/src/api/socket.js` and `constants/Config.js` shows its input comes from the configured `BASE_URL` origin, with path/query stripped, not from user-authored card text or links. The evaluation fixes that origin to `http://projects.invalid:1337`; the prepared gateway fixes the production host. An upstream Socket.IO migration should remove this dependency eventually; no broad local replacement was written.

The remaining client audit results include build tooling not shipped as runtime services. Source maps showed no affected figlet, webpack dev-server, compression, proxy-addr, SVGO, source-map-js, shell-quote or sprintf-js modules in the compiled browser output. Cunningham/UI-kit package reports inherit the figlet build-helper issue; the flagged formatter was not a mapped browser module. The build processes only pinned source and assets, does not serve a development server, and has no production credentials. Dependency reports and source-map evidence remain in the private report directory; absence from this audit is not a universal security guarantee.

The native Docker recipe needed three reproducible adjustments: npm 11.19.1 for its lockfiles, applying upstream's existing UI patches after copying client source, and writing attachments to the actual production path `/app/attachments`. The upstream Photoswipe caption patch, using text rather than HTML, was preserved. No application backend, export service or login system was replaced.

## Privacy, storage and recovery

`THEME={}` disables the optional external government widget/feedback configuration. Fonts and assets are local. SMTP, S3, webhooks and the statistics API token are unset. The stock production bundle excludes its development Redux logger. Native PostgreSQL state contains accounts, boards, cards, comments/actions, permissions, notifications and authentication sessions; uploads use separate local directories. Sessions include IP address and user agent. The data is ordinary server-readable application data, not end-to-end encrypted.

Browser cookies carry the application's access token/version, and local storage holds theme preferences and OIDC state/nonce/ID-token information when used. Closing a tab is not an erasure action. The native OIDC callback removes its state/nonce entries after reading them; logout revokes the tested access token. No visitor analytics or cross-service profiling was added.

The app can render user-authored external Markdown images. The prepared/tested gateway blocks these with same-origin `img-src`; optional external widgets, frames and external connections are also denied. This protects reading a board without disabling ordinary links that a user deliberately opens. CSP permits native inline runtime settings/styles; it is not a substitute for authentication or content escaping. Native WebSockets and local downloads remain allowed.

Application egress is limited to its own PostgreSQL instance in the unpublished pilot; gateway egress is limited to the app. The integration recipe must add only the existing identity endpoint. No arbitrary Internet-fetch permission is needed for the reviewed native workflow. Upload bodies are capped at 10 MiB by Nginx; an oversized request returned 413. This is a per-request ceiling, not a total account quota. Read-only containers, PID/CPU/RAM limits and bounded temporary storage are configured. Nginx access logs are off; container logs rotate at two 1 MiB files. Native warn/error logs can contain identifiers and authentication metadata. The pilot additionally uses a 16 MiB temporary log directory; the integration environment selects native `LOG_FILE=/dev/null` while retaining bounded console logs. No time-based log retention is invented.

Native Delete is not immediate physical erasure. Project, board, card and attachment metadata can move to the `archive` table; project deletion can leave child attachment files. Explicit attachment deletion made the tested download unavailable and removed its file. No automatic archive/session purge was found in the inspected source. These semantics must be stated plainly in any future data guide. No real retention was shortened and no cleanup mechanism was invented to disguise the behavior.

Recovery used a native PostgreSQL custom-format dump and restored it into a separate disposable database, comparing five table counts and fictional card contents. A separate filesystem archive was extracted into a temporary directory and the fictional attachment bytes matched. That is an operator recovery test, not a verified user export/import feature. Trello import exists. A follow-up source review found the native BoardActions → Export as CSV path; its pure export function was exercised with fictional data and a stubbed browser download, not through a restarted live UI. The CSV contains list, card name/description, assignee names, label names, due date, completion status and completed/total task count. It omits task text, comments/history, attachment files, permissions and account settings; no matching native CSV/project restore was found. It is a partial user export, not a complete portable backup. Exported fields are CSV-quoted but spreadsheet-formula prefixes are not neutralized; treat untrusted card text as text when opening it. Evidence: client/src/utils/export-cards-to-csv.js, BoardActions.jsx, and private csv-source-check.json. The pilot has no scheduled backups or promised backup-retention period; future integration must use the actual established operational schedule.

## Verification and integration state

The native test exercises project/board/list/card creation, card movement, attachment upload/download, separate-account access denial, explicit attachment deletion, project archival and token revocation. The browser check exercises native English and Spanish labels and is separate from the API-only local login used to seed its session. Current upstream Spanish coverage is partial: new empty-dashboard copy falls back to English, while native card labels translate. Its existing Spanish contains tú forms. No full voseo rewrite of this upstream application was performed; Utilibre-authored guide/policy copy remains subject to the voseo requirement.

The source supports OIDC and local API accounts, but its current browser login presents only an OIDC button. A new password form was not added. `configure-oidc.py` reuses existing authentik `utilibre-approved` and verified-email policies, a strict `/oidc-callback`, and minimal signed name/username/email claims. Neither that client nor its proposed public hostname has been activated. The native button still displays ProConnect branding and has no configuration label override; a separate small branding change would be needed before presenting it as Utilibre login.

Final browser results: both account-language settings loaded native card labels, remote Markdown images were blocked by CSP, and there were no actual external requests or JavaScript page errors. The intentional CSP denials are recorded separately from application errors. Both evaluation and prepared production Nginx configurations passed `nginx -t`; source patch apply/reverse, Python/JavaScript/shell syntax and compose validation passed.

Final report paths: `/opt/utilibre/reports/planka-fork-20261009/native-check.json`, `browser.json`, `boundary-resource.json`, server/client audit JSON and bounded build logs.
