## Access and resource bounds

The public host is `chess.utilibre.org`; gateway `10.10.1.43:3214` accepts the separate Caddy edge, 10.10.1.3. It also binds loopback for operator checks. The app has no published port, no account registration and no outside network. Caddy configuration is in `deployment/family-chess/Caddyfile`. A separate gateway ingress network is required because this Engine does not publish ports from an internal-only bridge. Scoped firewall rules block new outbound connections and other inbound sources; the gateway can reach only the chess application.

The app has one CPU, 256 MiB RAM, 80 PIDs, a read-only root and 32 MiB temporary space; the gateway has 0.25 CPU and 64 MiB. Two native Gunicorn workers have twelve threads each. Upstream caps SSE streams at six per worker and three per client IP, with polling fallback. This configuration is a small pilot, not a measured high-concurrency guarantee. New games are limited to two per minute per address, burst two, and ten per minute overall, burst three. Ordinary dynamic requests have a separate ten-per-second limit with burst twenty. Shared-network visitors can share those limits. SQLite has a 256 MiB page-count ceiling; exhaustion must be investigated, not solved by deleting users' games.

The tiny source patch uses cryptographic randomness for the native eight-digit identifiers, enables Django's native language-switch route, adds equivalent EN/ES data notes and portal links, corrects native board resizing without changing moves, and provides Spanish through the existing gettext system. Eight digits do not make a private document link. Occupied seats belong to sessions; anyone with the game code can watch and take a vacant seat. There is no password-protected room or verified player identity.

## Data, exports and deletion

The server can read game identifiers, board state, moves, reservations, session identifiers and seat-reclaim credentials. There is no chat or uploaded-file storage. The app uses secure HttpOnly session/reclaim cookies; language and CSRF cookies have their separate purposes. A browser reopening a restored session may retain access. Never describe closing a tab as deleting the game.

Native lifecycle rules: reservations last three minutes, inactive seats are freed after twenty minutes, abandoned games are marked after both players have been absent for two hours, and games older than seven days from creation are deleted. The installed minute timer runs `cleanup_games` and Django's `clearsessions`. These are the upstream rules selected for a newly installed service; existing services' retention was not changed. Previous snapshots are unaffected by active deletion.

No native game download, import or immediate-delete control was established in this release. Do not promise PGN export or full portable game history. The state endpoint is not documented as a user export. A user can keep a screenshot or notes on their device, but that does not reopen a playable game here. An identified early-removal request can be handled by the operator; do not promise automatic removal merely on receipt. Other participants can retain their own copies.

The daily 06:40 UTC timer, delayed up to ten minutes, uses SQLite's consistent backup API and saves the private configuration on this VM. No automatic expiry and no off-site copy are configured. The backup refuses below 5 GiB free. Checks include SQLite integrity and foreign keys; an independent copied-database test reopened the exact fictional board and two moves. This does not establish recovery of another physical server. A restore requires stopping this service, retaining the current files for rollback, installing the chosen database and matching private settings with uid10001 ownership, then starting the pinned image and checking it before routing traffic. Never restore over live games during a test.

## Logs, indexing and providers

Nginx access logging is off. Referrer-Policy is same-origin so native HTTPS form-CSRF verification works; no referrer is sent to another origin. Django/Gunicorn warnings and errors and gateway warnings go to Docker logs, bounded at two one-MiB files per container. This is size rotation, not a time-retention promise; errors can include request paths/game identifiers. System journal and Caddy/Cloudflare/provider records have their separately documented retention, which this app cannot establish. Static assets retain seven-day browser caching; dynamic responses use no-store. The app sends no visitor analytics and makes no external browser resource requests in the performed checks. Deliberately followed upstream/portal links are separate navigation.

The verified public path is browser → Cloudflare HTTPS proxy → Caddy → this gateway → app. Root wildcard DNS routes the host through Cloudflare; the earlier HTTP525 before edge configuration is resolved. The service is noindex; robots allows crawling so the directive is visible. A game code or noindex is not confidentiality. Both security.txt paths redirect to Utilibre's canonical contact. Germany hosting and the shared physical edge location follow the owner's confirmed facts; they do not determine the operator's legal establishment.
