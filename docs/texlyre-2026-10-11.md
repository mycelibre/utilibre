## Privacy and limitations

Configuration enables native air-gap mode and forces remote collaboration
offline. Signaling, filesystem sync, remote package endpoints, status feeds and
template API are empty. Remote bibliography, backup, diagram embeds and language
server plugins are disabled. CSP permits only this origin plus local blob/data
resources; no broad CORS or outside compilation fallback. Only GET/HEAD are
accepted by the server. Gateway access/error logging and container logging are
disabled. Cloudflare delivers assets and still processes connection metadata;
this is not anonymity or a provider-internal retention certification.

The tested workflow stores source, accounts, compiler cache and PDF locally.
Native guest sessions expire after 24 hours; logout also ends the guest session.
A full native account is local IndexedDB, not Authentik, online storage or email
recovery. It does not guarantee encryption of every project against another user
of the same browser profile. Export PDF and native project ZIP before clearing
site data. No server document backups or retention changes are involved.

The interface is English. EN/ES portal guides use its real control names. A
keyboard/larger screen is recommended; no physical-phone or Opera compatibility
claim. Not every desktop TeX package works. Basic/Recommended/Extra bundles are
available from this origin; SwiftLaTeX options are removed because its separate
package server is not deployed. Offline operation is not advertised: the native
service worker remains, but its full lifecycle has not been acceptance-tested.

## Resource evidence

Before publication: 16 logical CPUs, 34 GiB RAM, about 20 GiB available, root
disk about 29 GiB available. The excluded temporary-data disk is untouched.
The generated static build occupies about 927 MiB, excluding build dependencies
and source archives. This is storage/bandwidth, not per-visitor server compute.
The shared gateway retains its 1 CPU / 192 MiB ceiling, not a concurrency SLA.

The first tested Recommended/pdfTeX compilation requested 237,948,460 bytes
(226.93 MiB) of uncompressed compiler/package assets: worker, pipeline, biber
helper, WASM, engine JS and Recommended JS/data. HTTP compression can change
wire bytes; browser caching is not a permanent download guarantee. The catalogue
warns of approximately 227 MiB plus editor resources before launch. Compilation
uses the visitor's memory/CPU; there is no measured device-memory ceiling.
After discussing alternatives, the owner chose to retain this local-compilation
design and recommended bundle, not a server compiler or reduced package set.

## Minimal glue and reproducible update

`deployment/texlyre/instance-config.ts` uses upstream configuration. `prepare.mjs`
replaces the existing privacy disclosure with instance facts, points the native
source link to our source offer, removes unsupported SwiftLaTeX menu options,
disables unused embed downloads, corrects guest collaboration wording and pins
security dependency overrides. No editor/compiler/encryption algorithm is
rewritten. `nginx-server.conf` supplies origin isolation, CSP, cache revalidation,
ACL and logging policy. Portal data and guide files reuse existing templates;
Impeccable guidance preserved the established design without new portal CSS.

Use `sh deployment/texlyre/rebuild.sh` with Node 24.14 or a reviewed compatible
version. It builds from the pinned upstream, committed npm lock and native
generation/build scripts; runtime assets are checked before publication. Review
advisories and upstream release changes on updates. Do not auto-deploy latest.
The source offer includes modified app source, BusyTeX wrapper source, licenses,
dependency lock, configuration and build instructions, not private runtime state.
Upstream binary component sources/build references remain in their manifests;
the published prebuilt WASM was not independently rebuilt bit-for-bit.

## Verification

Chromium 151 on Linux, desktop 1440×1000, normal TLS through the actual Caddy edge
with LAN DNS override, using fictional `latex-practice.tex` only:

- Guest project creation and local file import; native pdfTeX compilation;
  PDF preview and download pass. PDF.js extracted Spanish accents and `2 + 3 = 5`
  from the downloaded PDF, not merely from editor text.
- Native TeXlyre ZIP export, reload persistence, import as a new owned copy and
  recovered editable source pass. Import requires selecting the detected project
  and clearing **Import as collaborator** when restoring as an owned copy.
- Native guest-to-full-local-account upgrade and reload preserve the editable
  source, without a server account request. No credentials from a real user were
  used. The independent public Cloudflare route also loads and opens the guest
  consent dialog with no outside-origin requests observed.
- A 390×844 mobile-emulated visit was inspected, not a real phone test. Upstream
  retains a 1200 px desktop viewport by default, so fitting its scroll width is
  not evidence of a readable phone editor. Keep the larger-screen recommendation.
- No external HTTP requests, document POSTs or browser errors observed during
  this journey. This evidence is bounded to tested paths, not every optional
  upstream feature or imported malicious document.
- Production build and clean locked npm install pass. Production `npm audit`
  reports zero known findings after six dependency override fixes; this does not
  audit bundled C/WASM binaries. Native BusyTeX/archive/sanitizer unit suites:
  63 tests pass.

## Rollback

Remove `texlyre` from `ENABLED_SERVICES` and unset `PUBLIC_LATEX_URL`; restore the
previous portal image `public-utility-portal:0.1.0-librespeed-20261011` and recreate
only the portal. Disable the latex Caddy block if the application itself must be
unreachable. Do not stop the shared gateway or clear anyone's browser storage.
Preserve the origin and export path where possible: local accounts/projects are
tied to it. Rebuild or restore the reviewed static release to recover application
files; the server cannot restore visitors' documents.
