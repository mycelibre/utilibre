# Anubis for Redlib

Deployment pin: official unmodified Anubis 1.27.0, commit
`d39e26cedcc96bea5e4915297c756e7eec74aaf7`, MIT license, image manifest digest
`sha256:8828275668b7bc675679f100970f9714f731388fbbf66ae94de8aca952e3fc4a`.

Anubis is the only service published on the private Redlib ingress port. It
challenges ordinary browser traffic and forwards successful requests to the
unpublished `redlib:8080` container.

The policy follows Anubis's v1.27.0 default rules, retains its mild difficulty-2
browser challenge, and allows only the two endpoints needed by the official
Redlib instance updater: `/info` and `/` with the updater's exact user agent.
The optional Thoth geo/ASN rules are omitted because no Thoth client is used.

The bbolt store under `data/anubis/` contains short-lived challenge state. The
Ed25519 signing key is generated by `scripts/init-secrets.mjs` under `secrets/`.
Neither path is committed. Metrics bind only to the container loopback address.
The effective metrics/health listener is `127.0.0.1:9090` inside the container
and has no host mapping.
Challenge rows have a logical 30-minute TTL; freed bbolt pages may remain until
compaction/deletion. Successful browsers receive a 24-hour host-only Secure,
HttpOnly, SameSite=Lax, Partitioned authorization cookie. Normal logging is
WARN/error and Docker rotates at 10 MB times three files. The container ceiling
is 0.25 CPU, 128 MiB RAM, and 128 PIDs.

`CUSTOM_REAL_IP_HEADER=CF-Connecting-IP` is safe only while the public origin is
restricted to Cloudflare. If Cloudflare is removed, change the trusted header
strategy before exposing the site.

Emergency rollback (data is preserved):

```sh
docker compose --profile privacy-frontends stop anubis
docker compose -f compose.yaml -f config/anubis/rollback.compose.yaml \
  --profile privacy-frontends up -d --no-deps --no-build redlib
```
